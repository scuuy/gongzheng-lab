# 工证 Lab · 评委问答

**1. 为什么需要这个产品？**
CAD/CAE 自动化交付跨越参数、几何、网格、求解输入和报告。一个环节更新而其他环节沿用旧版本，仍可能生成可打开的文件和看似合理的数字。我们把这些关系变成可重放的验收条件。

**2. AI 在哪里？**
AI 负责根据失败证据提出参数修改；可信适配器负责执行，独立验收端负责判断。原型提供模型无关 JSON 契约。演示附带两次真实 gpt-6-astra 网关调用提案，Web 按钮重放保存的提案。当前没有在 Web 中集成实时推理和密钥管理。

**3. 与普通文件校验、单元测试有何区别？**
文件哈希只能证明字节关系；这里还会实际重开 STEP、检查参数变型、重算 CalculiX，并核对网格和求解输入中的工程语义。平台本身仍属于测试和验收工具，价值在于领域适配器及可追溯证据。

**4. 与 CAD/CAE 软件是否竞争？**
它调用既有建模、网格与求解工具，作为自动化交付后的验收层。未来可通过适配器接入其他软件；当前并未实现这些集成。

**5. 怎样避免模型修改标准来通过？**
提案只允许有限几何字段；验收要求来自独立可信输入。对外部智能体使用 CLI 时必须传入 --requirements 的独立规范路径。内置示例为受控演示，不是任意上传的安全平台。

**6. 结果是否证明总体检出率 100%？**
没有。六个案例是预先设计的回归：一个正常对照和五种缺陷。它们验证明确机制，不是有代表性的工业抽样。两次模型提案通过也不是难度评测或 pass@K 结论。

**7. 为什么正负载荷需要单独检查？**
线弹性条件下，反转载荷可能得到相同位移模长。仅比较最大位移会漏掉方向错误，所以同时检查受支持求解输入的载荷、约束、材料、节点和单元。

**8. 当前最大技术限制是什么？**
只支持一个参数化支架、有限变型和线弹性工况。网格与 CAD 之间只是包络及体积粗检查；没有任意网格等价证明、网格收敛认证、接触、非线性或疲劳分析。

**9. 如何保证开源合规？**
自有源码和合成示例采用 Apache-2.0；第三方工具保留各自许可证，附依赖说明。本次分发源码和构建配方，不分发预构建工具镜像。未来若分发第三方二进制，需要单独落实对应许可证义务。

**10. 首批用户和商业化路径是什么？**
先面向 CAD/CAE 智能体开发团队、参数化设计团队和工程自动化研究团队，验证真实设计变更中的误报/漏报及复核耗时。商业方向是企业适配器、验收规则维护、部署与技术支持，尚未取得客户收入验证。

**11. 为什么认为可扩展？**
验收输出、提案格式与原生工具适配器已有分层。下一步先增加第二类几何模型和独立反例，验证契约是否真正通用，再考虑复杂求解器和审批系统。

**12. 成本、速度与模型身份如何解释？**
两次调用分别约 14.28 和 102.29 秒，为模型推理耗时，不包含完整原生重算。费用 unknown。gpt-6-astra 是网关返回标识，未独立认证底层模型身份；验收结论不依赖该名称。
